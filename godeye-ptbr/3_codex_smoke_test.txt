Seu objetivo é criar um roteiro prático, objetivo e executável para validar rapidamente se o projeto continua funcionando nas áreas essenciais.

==================================================
1. OBJETIVO DO SMOKE TEST
==================================================

Criar um plano de Smoke Test que valide o funcionamento mínimo e essencial do projeto após alterações, merges, builds, releases ou mudanças importantes.

O Smoke Test deve responder:

“O projeto abre, roda e os fluxos principais continuam funcionando?”

O plano deve focar em:
- inicialização
- build básico
- telas principais
- fluxos críticos
- persistência básica
- permissões essenciais
- integrações principais
- import/export, se existir
- navegação
- estados vazios
- estados de erro básicos
- regressões óbvias
- comportamento mínimo esperado

Não transformar em teste exaustivo.
Não transformar em auditoria.
Não transformar em QA completo.
Não transformar em checklist infinito.

==================================================
4. REGRAS DO PLANO
==================================================

O plano deve ser:

- claro
- direto
- executável
- organizado por prioridade
- específico para o projeto
- baseado no resumo existente
- útil para rodar manualmente ou orientar automação futura
- separado por plataforma, quando aplicável
- sem opinião desnecessária
- sem sugestões de features
- sem correções de código
- sem auditoria profunda

Cada teste deve conter:
- ID
- nome do teste
- objetivo
- pré-condições
- passos
- resultado esperado
- tipo de execução
- prioridade
- observações, se necessário

==================================================
5. CLASSIFICAÇÃO DE PRIORIDADE
==================================================

Classifique cada teste como:

CRÍTICO:
Teste que valida se o projeto abre, compila, inicia ou executa fluxo principal indispensável.

ALTO:
Teste de fluxo importante que, se quebrar, afeta uso normal.

MÉDIO:
Teste de fluxo secundário ou comportamento importante, mas não bloqueante imediato.

BAIXO:
Teste de polimento, fluxo menos frequente ou validação complementar.

==================================================
6. TIPOS DE EXECUÇÃO
==================================================

Classifique cada teste como:

MANUAL:
Precisa ser feito por uma pessoa.

AUTOMATIZÁVEL:
Pode virar teste automatizado no futuro.

COMANDO:
Pode ser validado por comando de terminal.

APARELHO REAL:
Precisa ser validado em dispositivo físico, emulador específico, navegador real, ambiente real ou hardware real.

AMBIENTE:
Depende de servidor, API, banco, arquivo, sensor, permissão ou serviço externo.

Pode usar mais de um tipo por teste.

Adapte ao projeto.

- navegador

- rodar testes
- build debug

- gerar código

- [ ] Navegação principal funciona

- [ ] Build principal conclui
- [ ] Testes existentes passam

Adaptar ao projeto.

## 13. Smoke Test de persistência
Se o projeto possui persistência, validar:

- criar dado básico
- editar dado básico
- remover dado básico, se aplicável
- fechar e abrir novamente
- confirmar que o dado permanece
- confirmar que não duplica indevidamente
- confirmar que estado vazio funciona

Adaptar aos dados reais do projeto.

## 14. Smoke Test de integração externa
Se o projeto possui integrações externas, validar:

- integração disponível
- integração indisponível
- permissão negada
- retorno vazio
- erro básico
- timeout ou falha simples
- fallback, se existir

Não aprofundar em segurança ou performance.

## 15. Smoke Test de UI essencial
Validar o mínimo de interface:

- tela inicial
- menu/navegação
- botões principais
- estados vazios
- mensagens de erro básicas
- loading básico
- tela pequena, se aplicável
- rolagem, se aplicável
- formulário, se aplicável

## 16. Smoke Test de build/release
Validar, conforme o projeto:

- build de desenvolvimento
- build de release, se aplicável
- assets carregando
- arquivos de configuração presentes
- app/serviço inicia após build
- não há erro crítico no primeiro uso

Não fazer análise profunda de release.

- Build principal foi gerado com sucesso.
- Dados básicos persistiram corretamente.
- Nenhum bloqueador foi encontrado.

- Tela inicial apresenta crash.
